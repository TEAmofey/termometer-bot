# Развёртывание через Git

По просьбе владельца проекта код синхронизируется только через Git. Это правило распространяется на всех агентов; см. [AGENTS.md](../AGENTS.md).

## Порядок обновления

1. Проверить локальный `git status`, изменения и необходимые тесты. Коммитить только файлы задачи; не включать посторонние изменения.
2. Создать коммит и отправить его в соответствующую ветку `origin`. Зафиксировать SHA, который должен быть развёрнут.
3. На сервере проверить `git status`, текущую ветку, `HEAD` и remote в каталоге приложения. Не предполагать имя ветки по умолчанию.
4. Если рабочее дерево изменено, сравнить серверные правки с локальным репозиторием и сохранить нужные правки в Git. Не затирать их принудительно. Это особенно важно при первом обновлении после прежней доставки файлов напрямую.
5. Получить изменения через `git fetch` и обновить согласованную ветку через `git merge --ff-only` либо `git pull --ff-only`. Проверить, что `HEAD` соответствует выбранному SHA. Для отката также использовать Git.
6. Выполнить необходимые проверки и миграции из этой версии. Перед изменением данных создать резервную копию; если миграция требует остановки бота, остановить только процесс `thermometer`.
7. Перезапустить бот и проверить процесс, свежие логи и результат изменения.

Команды управления существующим PM2:

```sh
env PM2_HOME=/home/mofeytea/.pm2 pm2 stop thermometer
env PM2_HOME=/home/mofeytea/.pm2 pm2 restart thermometer
env PM2_HOME=/home/mofeytea/.pm2 pm2 logs thermometer --lines 30 --nostream
```

Не перезапускать остальные приложения PM2. Не запускать отдельный экземпляр бота рядом с существующим процессом.

Не переносить код через `scp`, `rsync`, архивы или запись файлов по SSH. Не редактировать исходники непосредственно на сервере. Если Git-доступ не работает, исправить доступ; не заменять Git копированием файлов.

`config.py`, секреты и данные БД остаются вне Git. Логи и резервные копии также не добавлять в репозиторий. Правило Git относится к исходникам, тестам, документации и скриптам миграций, а не к содержимому БД.

## Доступ к Telegram на новом сервере

При развёртывании 12 октября 2026 года адрес `api.telegram.org`, полученный через DNS (`149.154.166.110`), не отвечал с нового сервера. Проверен HTTPS-доступ к Telegram через `149.154.167.220` с сохранением имени хоста и проверки TLS. В `/etc/hosts` добавлено сопоставление `149.154.167.220 api.telegram.org`; исходный файл сохранён в `/etc/hosts.before-thermometer`. Это настройка сети сервера. Если Telegram снова недоступен, проверить актуальную доступность адреса и DNS.
